## 1. 核心定义与设计思辨 (Core Definition & Speculation)

### 1.1 从“单机智能”到“群体智能”
单一 Agent 的进化速度受限于用户的操作频率。而 **AceAgent-Swarm** 的愿景是构建一个“硅基互助社区”。
*   **场景**：用户 A 昨天教会了 Agent 如何在“瑞幸咖啡”App 里领券。
*   **理想**：今天用户 B 刚下载瑞幸 App，他的 Agent 应该**天生就会**领券，无需从头学习。
*   **载体**：**Skill Blueprint (技能胶囊)** —— 一种可分发、可验证、可执行的标准化数据包。

### 1.2 信任与安全的挑战
共享经验的最大风险是**投毒 (Poisoning)**。如果恶意用户上传了一个名为“领红包”但实际执行“转账”的蓝图，后果不堪设想。因此，群智网络的核心不是分发，而是**验证 (Validation)**。

## 2. Skill Blueprint 数据协议 (The Protocol)

Blueprint 不仅仅是脚本，它是一个**带有环境约束的状态机 (FSM)**。

### 2.1 胶囊结构
一个完整的 `.skill` 文件包含：
1.  **Metadata**: 作者信誉分、App 版本范围、适用 OS。
2.  **State Graph (拓扑)**: 包含 $N$ 个页面骨架（见文档五）。
3.  **Transitions (动作)**: 页面间的跳转动作，包含意图 Key 和相对坐标矩阵（见文档三）。
4.  **Guardrails (护栏)**: 执行该 Skill 时的安全断言（如“禁止点击含‘支付’字样的按钮”）。

## 3. 分布式同步机制 (Synchronization Mechanism)

### 3.1 冷启动：探路者机制 (The Pathfinder)
*   **角色定义**：
    *   **Pathfinder (探路者)**：拥有高性能 System 2 (GPT-4/Claude 3.5) 权限的高端节点。负责探索未知。
    *   **Follower (跟随者)**：仅运行 System 1 的轻量级节点。负责消费蓝图。
*   **流程**：
    1.  Follower 请求执行未知任务。
    2.  云端无蓝图，下发**“探索悬赏”**。
    3.  Pathfinder 节点接单，利用 VLM 慢速探索成功，上传草稿蓝图。

### 3.2 灰度验证与共识 (Canary & Consensus)
新上传的蓝图处于 `Untrusted` 状态。
1.  **隐私擦除**：云端自动清洗蓝图中的 OCR 敏感词（手机号、金额），只保留通用 UI 词汇。
2.  **金丝雀发布**：下发给 1% 的高活跃度 Pathfinder 进行“影子测试”或“实盘测试”。
3.  **PoS (Proof of Success)**：
    *   Agent 执行后，上报**“状态指纹匹配度”**。
    *   当连续 50 个不同设备上报“匹配度 > 95%”且“未触发安全护栏”，蓝图晋升为 `Stable`。

### 3.3 全网热更新 (Hot-fix Propagation)
当 App 版本更新导致 UI 突变（如“购物车”从底部移到了顶部）：
1.  **熔断**：全网大量 Follower 上报“锚点丢失”错误。
2.  **召回**：云端立即撤回旧版蓝图，标记为 `Deprecated`。
3.  **重生**：Pathfinder 重新探索新版 UI，生成 v2.0 蓝图。
4.  **推送**：新蓝图在分钟级内覆盖全网，用户无感知修复。

## 4. 安全风控体系 (Security Architecture)

### 4.1 语义防火墙 (Semantic Firewall)
即使蓝图通过了验证，在 Follower 端执行时，仍有最后一道防线。
*   **敏感操作拦截**：
    如果蓝图包含涉及资产（Pay, Transfer）、隐私（Export Data）的意图 Key，系统强制要求**生物识别认证（FaceID/指纹）**。
*   **视觉核验**：
    执行点击前，OCR 再次检查目标区域文本。如果意图是“取消”，但点击位置文字是“确认”，立即熔断并举报该蓝图。

## 5. 总结 (Summary)

群智网络是 AceAgent-Swarm 的护城河。
它将原本孤立的 AI 算力连接成了一张**动态更新的自动化地图**。在这个网络中，每一个 Agent 既是老师也是学生，共同构建着人类 GUI 操作的全部知识图谱。
