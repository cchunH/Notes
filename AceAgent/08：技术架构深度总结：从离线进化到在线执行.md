
## 1. 核心设计范式：双系统协同 (System 1 & System 2)

AceAgent-Swarm 的底层架构参考了人类认知的双系统模型，旨在解决当前 Agent 系统在移动端运行时的“推理延迟”与“执行脆弱”问题：
*   **System 2 (推理层/大脑)**：利用高参数量大模型（如 Claude 3.5/GPT-4o）进行长链条逻辑规划与未见页面的语义分析。其特点是**高能耗、高延迟、高逻辑上限**。
*   **System 1 (执行层/小脑)**：利用本地化轻量级算法进行页面指纹匹配与动作投射。其特点是**低功耗、亚秒级响应、强稳定性**。

本系统的核心逻辑在于：**通过 System 2 的首次探索，沉淀为 System 1 的结构化经验；在后续重复任务中，由 System 1 直接闭环执行。**

---

## 2. 离线阶段：经验沉淀与骨架提取 (Offline Reflection)

离线阶段是系统进化的核心，其任务是将非结构化的历史操作日志（Trace Logs）提炼为高精度的**技能蓝图（Skill Blueprint）**。

### 2.1 多帧交集与静态骨架识别 (Structural Intersection)
系统对同路径（App/Activity）下的多张历史截图进行**结构化差分运算**：
*   **去噪机制**：通过对比同一页面在不同时间、不同内容下的 UI 树（Accessibility Tree），识别出属性值不断变化的动态节点（如广告、时间、Feed流）。
*   **骨架固化**：将所有在多帧中保持属性（Text/Role/Layout）恒定的元素标记为“幽灵骨架”。这些元素构成了页面最稳固的拓扑指纹。

### 2.2 星群锚点选取算法 (Constellation Selection)
在骨架中，系统自动筛选出 3-5 个关键节点作为定位基准，分为两类角色：
*   **核心锚点 (Core)**：选取分布于屏幕 Top 15% 与 Bottom 15% 安全区内的显著元素（如导航标题、返回键、全局 Tab）。这些点极少受业务滚动影响，作为计算坐标的数学原点。
*   **辅助锚点 (Auxiliary)**：选取页面中部的语义唯一性强的静态元素。其作用是在指纹匹配时增加权重，防止结构相似页面的身份误判。
*   **分散性优化**：采用空间非极大值抑制（NMS）算法，确保锚点物理分布最广，以应对局部遮挡风险。

### 2.3 动作参数化建模 (Action Parameterization)
对于在该页面执行的动作（点击、滑动），系统不存储像素坐标，而是记录目标点相对于锚点星座的**仿射变换参数**（如重心坐标比例）。这种数学表达确保了动作指令具备“分辨率免疫”特性。

## 3. 在线阶段：指纹检索与弹性执行 (Online Execution)

在线阶段追求极速响应，通过 System Key 约束与几何投射实现无感知操作。

### 3.1 意图标准化与意图库约束 (Intent Canonicalization)
*   **Schema 强约束**：系统通过 Function Calling 强制 LLM 仅输出预定义的标准化意图 Key（如 `com.app:TAP:SUBMIT`）。
*   **检索路由**：系统根据 `App_ID + Intent_Key` 在本地向量数据库中瞬间锁定对应的“技能蓝图”。

### 3.2 页面状态指纹匹配 (Fingerprint Matching)
*   **局部感知**：Agent 仅对当前屏幕的安全区进行极速 OCR 或特征提取，无需全屏分析。
*   **Quorum 校验**：将实时感知的元素与蓝图中的 3-5 个主辅锚点比对。采用“法定人数”机制，只要匹配度达到阈值（如 5 选 3），即确认页面匹配成功。这一步有效解决了弹窗遮挡、UI 微调带来的干扰。

### 3.3 仿射坐标投射 (Affine Projection)
*   **动态计算**：系统根据当前屏幕上找出的 3 个核心锚点实际坐标，计算出相对于离线基准的**变换矩阵（Matrix）**。
*   **坐标映射**：将蓝图中的参数映射为当前机型（如 21:9 的长屏手机或折叠屏）的绝对像素坐标，直接下发硬件级指令。

---

## 4. 群体智能：蓝图联邦与自动纠偏 (Swarm Evolution)

系统通过云端社区实现经验的指数级增长。

### 4.1 蓝图打包与共享
每个稳定的操作被封装为 **Skill Blueprint**。它包含环境约束、状态机逻辑和锚点组。新 Agent 启动时，通过 App 标识直接下载云端已验证的成熟蓝图，跳过 System 2 的探索阶段，实现“冷启动即专家”。

### 4.2 错误感知与自愈循环
*   **失效检测**：当多台设备反馈某蓝图匹配度大幅下降时，云端标记该 App 版本 UI 发生突变。
*   **探路者重构**：指派高性能节点（Pathfinder）重新调用大模型进行探索，生成新版骨架蓝图并全网推送。

---

## 5. 总结：技术价值与演进逻辑

AceAgent-Swarm 的完整链路实现了从 **“发散推理”** 到 **“收敛执行”** 的闭环：

1.  **离线端**：通过**多帧交集**解决“哪些 UI 元素是可靠的”问题，通过**空间分散选取**解决“如何抗遮挡”问题。
2.  **在线端**：通过**意图 Key 约束**解决“语义发散”问题，通过**仿射变换**解决“屏幕碎片化”问题。
3.  **群体端**：通过**蓝图联邦**解决“冷启动与集体演进”问题。

这种架构设计的核心优势在于：它不追求 AI 的“全知全能”，而是追求在特定 App 环境下操作的**绝对确定性**与**极致性能表现**。它是目前将 LLM 转化为高可靠移动端自动化工具的最优工程路径。
